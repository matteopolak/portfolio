# Search discovery and page metadata

## What it is

The site emits crawlable metadata, canonical URLs, social previews, structured data, `robots.txt`, and a build-generated XML sitemap. Everything is rendered into the static build, so search engines do not need client-side JavaScript to discover it.

## How it works

`src/components/Head.astro` owns page titles, descriptions, self-referencing canonical links, Open Graph and Twitter fields, and a Schema.org JSON-LD graph. The graph describes Matthew as the site publisher, normal routes as `WebPage`, and blog posts as `BlogPosting` with their publication date. `src/lib/urls.ts` removes Astro's static `.html` output filename from public canonicals so metadata and sitemap URLs stay aligned.

`src/pages/sitemap.xml.ts` is a prerendered Astro endpoint. At build time it takes the shared route list (`getRoutes()` in `src/lib/content`, also the WebMCP `navigate` allow-list), which excludes drafts, and writes absolute canonical URLs for the home, Projects, Blog, the playground index and each `/playground/<language>` page (from `src/data/code-demos.ts`), and every published post. Blog entries use their publication date as `lastmod`; static pages omit it because the repository does not track a reliable content-modification date. The prerendered `src/pages/robots.txt.ts` route allows normal crawling and advertises the sitemap using the same configured production origin.

## How to change it

- Add a new indexable static route to `buildRoutes` in `src/lib/content/routes.ts`.
- Keep blog posts in `src/content/blog`; published posts enter the sitemap automatically, while `published: false` posts stay out.
- Pass a concise, page-specific `description` to `Layout`. Blog metadata comes from post frontmatter.
- Change shared social image fields and structured data in `src/components/Head.astro`.
- Keep sitemap URLs and `rel="canonical"` URLs in the same canonical route form.

Do not add `priority` or `changefreq` to the sitemap; Google ignores both. Only add `lastmod` where the date represents a real significant content update.

## Configuration

`site` in `astro.config.ts` is the canonical origin and must remain the production HTTPS URL. The social preview uses the generated, content-hashed 512px icon derived from `src/assets/favicon.svg`. `portfolio.toml` provides the public name, biography, GitHub username, and LinkedIn slug used in structured data.

## Dependencies

The implementation uses Astro's static endpoint API and content collections. It makes no network requests at build time or runtime and adds no package dependency.

## Additions

- `Head.astro` also emits a `BreadcrumbList` (Home > section > page), `dateModified` and `image` on `BlogPosting` (posts have no separate modified date, so it equals `datePublished`), an RSS `<link rel="alternate">`, a web manifest link, and a 1200x630 `og:image` (`summary_large_image`) generated by `scripts/generate-favicons.ts`.
- `src/pages/rss.xml.ts` (`@astrojs/rss`) serves `/rss.xml` for published posts, without trailing slashes. `public/manifest.webmanifest` is static.
- **Everything meaningful is in the static HTML.** Svelte islands are SSR'd; do not use `client:only` for content, and never inject meta/link tags from client JS. Project descriptions on `/projects` are in the server HTML.
- `pnpm check:seo` (`scripts/check-seo.ts`, run in CI after the build) parses `dist/**/*.html` and fails on a missing or duplicate title/description, bad canonical (absolute, no trailing slash, matching the route), missing Open Graph/Twitter tags, `lang`, viewport, theme-color, favicon or manifest link, not exactly one `<h1>`, or JSON-LD that does not parse; it also checks sitemap, robots and the feed. `@astrojs/rss` is the one added dependency.
- Markdown alternates: every page except the playgrounds has `<link rel="alternate" type="text/markdown">` in `Head.astro` (path from `markdownPathFor` in `src/lib/content/routes.ts`) and a built `.md` file; `/llms.txt` indexes them. They are not in the sitemap because they are alternates of canonical pages; `check-seo` enforces the link, the file, the matching title, description and heading, and that llms.txt only links existing files. See [markdown-variants.md](./markdown-variants.md). `robots.txt` does not mention llms.txt, since there is no robots convention for it.
